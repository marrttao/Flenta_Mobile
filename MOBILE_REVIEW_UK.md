## Обсяг перевірки

Переглянуто React Native/Expo Router структуру, конфігурацію й npm-скрипти, API-клієнт, авторизацію та відновлення сесії, PKCE і посилання підтвердження, адаптери сховища, KYC, основні екрани банкінгу, фінансів і профілю, валютні хуки, UI-компоненти та автоматизовані тести.


## Виправлення

### 1. Збереження HTTP-статусу при нестандартному тілі помилки

Файл: `src/features/auth/api/httpClient.ts`.

Раніше відповідь на кшталт HTTP 401 із тілом `null` спричиняла помилку читання `problem.errors`. Загальний обробник перетворював її на мережеву помилку зі статусом 0. Сервіс сесії через це не запускав потрібне оновлення токена. Нестрічкове поле `code` також могло потрапити до коду, який очікує рядок.

Додано перевірку структури Problem Details. З validation-повідомлень беруться лише рядки, поля `detail`, `title` та `code` перевіряються за типом. Некоректне тіло більше не приховує справжній HTTP-статус. Окремий тест перевіряє повний ланцюжок: 401 із `null` → одне оновлення сесії → успішна повторна спроба.

### 2. Помилки захищеного сховища передаються сервісу сесії

Файли: `src/storage/adapters/secure-storage-adapter.ts`, `secure-storage-adapter.web.ts`.

Адаптери раніше перехоплювали помилки і завершували операції так, ніби вони вдалися. При невдалому видаленні refresh-токена сервіс сесії не міг відрізнити успішне очищення від збою.

Тепер помилки читання, запису й видалення передаються викликачеві. Наявний обробник `SessionService` може записати попередження у стан сесії; його показує екран входу. Для web серверне виконання без `window` залишається допустимим, а блокування `sessionStorage` у браузері більше не приховується.

Тести використовують справжній адаптер і сервіс сесії з підставним native bridge. Перевірено невдалий вихід, збереження попередження та повторне успішне видалення токена. Це не перевірка реального iOS Keychain або Android Keystore.

### 3. Послідовне читання та збереження списку валют

Файл: `src/features/currency/hooks/useUserCurrencies.ts`.

Раніше швидка зміна списку могла відбутися до завершення його початкового читання зі сховища, після чого старі дані перезаписували новий стан. Паралельні записи також не мали визначеного порядку завершення.

Операції додавання, видалення й перестановки тепер чекають завершення початкового читання. Записи поставлено в послідовну чергу. Формат збережених даних і ключ не змінювалися. Життєвий цикл цього хука окремим UI-тестом не перевірено.

### 4. Ключі сховища сумісні з прямим запуском тестів у Node 24

Файл: `src/storage/keys.ts`.

Початковий TypeScript `enum` зупиняв тести сесії з `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX`: штатне видалення типів Node не трансформує enum. Його замінено на об’єкт із `as const` та однойменний тип допустимих значень. Записи на кшталт `StorageKeys.REFRESH_TOKEN`, назви й рядкові значення збережено.

### 5. Компоненти узгоджено з правилами React Compiler

- `Loader.tsx` та `ToastItem.tsx`: замість читання `useRef(...).current` під час render використано штатний React Native `useAnimatedValue`. Значення анімацій, тривалість і стилі збережено.
- `AuthProvider.tsx`: об’єкт авторизації створюється через лінивий `useState(createAuth)`, що зберігає його на час життя провайдера.
- `KycProvider.tsx`: актуальна ідентичність сесії записується в ref у layout-effect, а не під час render. Під час очищення ref інвалідується, щоб пізній результат не оновлював демонтований провайдер.
- `ProfilePage.tsx`: прибрано дублювання імені з профілю через синхронний `setState` в ефекті. Окремо зберігається лише редагована чернетка; отримання профілю не затирає введений текст. Якщо користувач продовжив редагування під час збереження, нова чернетка залишається.
- `src/storage/test/StorageTest.tsx`: початкове читання винесено в асинхронну функцію з перевіркою актуальності перед оновленням стану.

### 6. Власні інструменти перевірки мобільного проєкту

Файли: `package.json`, `package-lock.json`, `eslint.config.js`, `.gitignore`, `README.md`.

- У `engines` зазначено Node `>=24.0.0`, відповідно до потреб наявних тестів і README.
- Шаблон тестових файлів взято в лапки; перевірено, що його обробляє сам Node 24 у Windows. Нові тести також автоматично входять у запуск.
- Видалено `reset-project`, який посилався на відсутній `scripts/reset-project.js`.
- Додано локальні dev-залежності ESLint та конфігурацію Expo, підібрані через `expo install`. Раніше `expo lint` у цій вкладеній папці знаходив конфігурацію Desktop, яка не охоплювала мобільний TypeScript.
- `.tools/` додано в `.gitignore` та ігнорування ESLint. Тут залишаються portable Node, npm-кеш, звіти та перевірочні експорти.
- До README додано команду lint.

Додавання lint оновило lock-файл і дедуплікувало шість вкладених записів. Порівняння зі стартовим lock-файлом не виявило зміни версій пакетів, які залишилися за тими самими шляхами. Основні React/React Native/Expo залежності в package.json не змінювалися.

## Результати перевірок

Використано локальний офіційний portable Node **24.22.2**, завантажений із перевіркою SHA-256. Системний Node не замінено.

| Перевірка | Результат |
| --- | --- |
| Початкове `npm ci` за lock-файлом | Успішно |
| `npm test` | 31 успішний тест, 0 помилок, 0 пропущених |
| `npm run typecheck` | Успішно |
| `npm run lint` | 0 помилок, 28 попереджень |
| Фінальний `expo export --platform all` | Успішно для Android, iOS та web, включно із серверним web bundle |
| `git diff --check` | Успішно |
| `npm audit --omit=dev` | 5 moderate, 0 high, 0 critical; не є чистою перевіркою без зауважень |

До наявних 22 тестів додано 9: два для нестандартних Problem Details, один для оновлення сесії після 401 із `null` і шість для адаптерів сховища та інтеграції з сесією. Native bridge підмінено лише в тестах.

Залишені lint-попередження переважно стосуються повторних імпортів; також є залежність ефекту callback-сторінки, dev-only `require`, невикористаний імпорт та попередження про однойменні тип і константу `StorageKeys`. Правила не вимикалися для приховування помилок.

Під час npm install загальний audit повідомив про 12 moderate-зауважень. Окрема перевірка без dev-залежностей показала 5 зауважень у ланцюжку `expo`, `@expo/cli`, `@expo/fingerprint`, `glob`, `minimatch`. Запропонований npm автоматичний fix включав несумісну зміну версії Expo. `npm audit fix --force` не застосовувався; це потребує окремого узгодженого оновлення SDK та повторної перевірки платформ.
