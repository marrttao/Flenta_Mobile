## Виправлення

### Сумісність native-залежностей

Чистий `npm ci` спочатку завершувався `ERESOLVE`: кореневий `react-native-worklets ^0.7.2` конфліктував із Reanimated та поточним Expo SDK.

За `bundledNativeModules.json` саме пакета Expo 58.0.25 встановлено сумісні точні версії:

- `react-native-worklets`: `0.13.0`;
- `react-native-reanimated`: `4.7.1`, явно зафіксовано в залежностях.

Lock-файл оновлено звичайним npm install. Повторний чистий `npm ci` успішний. `--force` і `--legacy-peer-deps` не застосовувалися. Оскільки це native-залежності, для перевірки вже встановленого development client потрібна його нова native-збірка; одного JS reload недостатньо для підтвердження сумісності.

### JWT і таймери

Файл: `src/features/auth/utils/jwtUtils.ts`.

Відсутній або нечисловий `exp` раніше міг трактуватися як непрострочений токен. Крім того, скінченний `exp` на кшталт `1e308` давав Infinity після множення на 1000. Тепер некоректний або переповнений термін дії повертає `null`, а `isTokenExpired` вважає його простроченим. Декодування JWT використовується лише для клієнтського таймера, не для підтвердження автентичності чи прав доступу.

Додано `tests/jwt.test.mjs`: коректні майбутні/минулі строки, UTF-8, відсутній exp, помилкові типи, переповнення і пошкоджені токени.

Файли: `useIdleTimeout.ts`, `useTokenExpiry.ts`, `AuthProvider.tsx`.

- Відкрите попередження прив’язане до конкретного `expiresAt`. Зміна сесії приховує старий діалог без синхронного скидання стану всередині ефекту.
- Якщо countdown почався вже після завершення строку, не створюється новий інтервал, який повторно викликає logout. Помилка фонового logout перехоплюється.
- Семпли часу прив’язані до свого deadline. Перше вимірювання виконується таймером, а попередній deadline не показується як поточний.
- `sessionInfo` тепер оновлюється через один таймер у провайдері, замість `Date.now()` під час render і застарілого useMemo. Читання sessionInfo не створює окремий таймер у кожному споживачі useAuth.
- Об’єкт сервісу авторизації створюється лінивим useState один раз на монтування провайдера.

Політику idle timeout щодо виходу при невдалому продовженні сесії не змінено.

### Типи та тестове оточення

- `src/storage/keys.ts`: enum замінено на константний об’єкт і однойменний тип. Це відновлює виконання наявних Node-тестів у strip-only mode. Ключі та їхні значення збережено.
- `src/features/theme/test/ThemeTest.tsx`: тип Palette охоплює обидві теми, а не лише світлу палітру. Це усуває помилку TypeScript для dark mode.
- `src/features/auth/test/AuthIdleTest.tsx`: асинхронне читання прапорців сховища відокремлено від оновлення стану; початковий результат не застосовується після очищення ефекту.
- У package.json додано вимогу Node >=24, лапки навколо шаблону тестів та прибрано reset-project, що посилався на відсутній файл.
- Відновлено локальні dev-залежності ESLint/Expo config і окремий eslint.config.js. Перевірка більше не покладається на конфігурацію Desktop.
- `.tools/` виключено з Git та ESLint; локальний Node, npm-кеш і перевірочні bundles не входять до коміту.

Lint-попередження залишаються видимими, переважно про імпорти та залежності хуків; правила не вимикалися заради проходження. npm також позначає обрану сумісну версію ESLint 9 як deprecated; це інструмент розробки, а не runtime-залежність застосунку.

Команди повторної перевірки з Node 24:

```sh
npm ci
npm test
npm run typecheck
npm run lint
```

Для export потрібно налаштувати HTTPS `EXPO_PUBLIC_API_BASE_URL`, потім виконати `npx expo export --platform all`. Локальні перевірочні артефакти зберігаються в `.tools`.
